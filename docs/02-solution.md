# 方案与设计取舍

Python 标准库 CLI + SQLite，原生实现有界模型循环，无框架依赖。复用项目一已改进的智谱请求协议和脱敏诊断，但项目二工具、持久状态和验收逻辑独立。

模型每轮接收用户约束、工具价目表、持久化状态和执行观察，自主选择下一工具或 finish。消息显式区分已执行的动作和工具结果，避免反复复述上一动作。运行器不把固定重试或 Mock 策略称为真实模型决策。

| 工具 | 输入 | 职责/约束 |
|---|---|---|
| search_materials | 无额外参数，使用请求主题 | 检索合成资料，收2单位、耗1分钟；缓存结果 |
| estimate_cost | variant | 根据账本重算总费用和剩余耗时，返回预算/时间缺口；免费 |
| generate_script | variant | 必须有资料和估算，重新检查预算/时限；基于事实模板生成可编辑场景与来源 |
| save_plan | variant | 必须有成功脚本、实际总费用和时间可行；原子保存 |

premium 生成成本10、耗时8；basic 成本6、耗时4。包含检索后总费用分别为12与8，总耗时9与5。失败生成假设收费0、耗时1；估算/保存成本及耗时为0。模型 API 实际费用不计入模拟账本。

预估并不收费；成功步骤才记实际模拟费用。生成前再次检查费用和时限，禁止依靠过期估算超预算执行。失败记录为 failed，不虚构生成结果。工具层脚本为确定性模板；真实模型负责规划决策，不要求再用模型生成脚本文本。

SQLite 保存 runs 状态及 plans 方案。幂等键为完整请求与资料/价目表内容摘要，相同内容可续跑，约束/资料变化视为新任务。故障注入开关不进入幂等键，因此去掉故障可恢复同一任务。BEGIN IMMEDIATE 内重读状态，重复成功步骤直接返回缓存，方案写入和状态保存处于同一事务。

每轮最多执行一个工具，默认最多14步；所有无效动作也消耗预算，达到上限明确 incomplete/limit_reached。模型可观察错误后重选方案、重试瞬时故障或停止。finish 没有保存或合理失败依据时会被拒绝；控制器不伪造模型决策。

智谱接口依据：https://docs.bigmodel.cn/cn/api/introduction ，普通 API 端点，不是 Coding Plan。真实 API 适配器此前在项目一连通；本项目尚未单独 live 验证。
